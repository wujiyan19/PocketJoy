# 全游戏去留审核：难度、重复游玩、玩法特色（2026-10-27）

> 执行状态：用户确认后已落实目录、模式合并及保留项整改。当前开放 64 个独立入口，具体完成内容与验证边界见[整改执行记录](game-retention-implementation-2026-10-27.md)。以下保留整改前的审核基线与原始证据，不能作为整改后实现的描述。

审核结论：当前 76 款不宜全部原样保留。建议 **38 款保留、26 款整改保留、5 款并为已有游戏的模式、7 款暂撤当前版本**。完成合并和暂撤后是 **64 个独立入口**，这是本轮判断的结果，不是预设数量目标。没有修改游戏代码、上架策略、路由、资源或战绩。

“整改保留”表示值得继续投入，逐项修正所列问题；不等于 26 款都必须立即隐藏。“暂撤”表示当前实现不足以支持独立入口，可重做后恢复。合并须先做好模式入口和历史成绩承接，再收起旧入口，不能直接隐藏而让玩法丢失。

- 基准提交为 `430624efff61f8b203b0781ac2ff6a4bde961bed`。审核包含当前未提交实现，特别是黑洞、漂移和棋类改动；不是只看提交版本。源码哈希保存在 [model-probes.json](game-retention-audit-2026-10-27/model-probes.json)，相关判断随实现变化需要复核。
- 方法是当前源码及调用链审阅、桌面模型抽样和相关既有回归。没有逐款真机试玩、用户访谈或留存数据；下列“复玩/特色”是产品判断，不是实际用户偏好或留存率测量。画面美术、触控手感、音乐同步和设备性能不在本轮实测范围。

- 未构建或安装新 HAP，本轮没有发布就绪或最终包真机验收结论。

## 判定口径

**难度**：有效＝改变反应窗口、资源约束、信息量、解题规模或对手策略；有限＝有变化但主要增加时长/数量，或没有校准实际解题难度；无效＝三档实际同规则，或可被同一个简单策略绕过核心挑战；不适用＝本来不提供分档，使用关卡进阶或统一规则。有效不代表已测定普通用户的胜率梯度。

**复玩**：强＝局面持续产生不同决策或可提升的操作表现；中＝能重复练习，但内容、进阶或成绩反馈较薄；弱＝固定内容很快见底，或重复同一操作就能完成。随机颜色、打乱顺序和更长流程不能单独证明强复玩。

**特色**：相对于本合集其他入口，是否提供不同的核心决策、操作方式或认知任务；不是声称原创或市面独有。强＝承担明显不同的体验；中＝类型成立但内容或表达较薄；弱＝与现有入口高度重叠，或名称承诺的核心体验未成立。经典规则、共用源码、没有长期养成均不是单独撤下的理由。

去留不以三项简单求和：明确的玩法绕过优先处理；难度按钮失效但核心玩法完整，优先去掉假分档或补规则；重复入口优先合并。没有长期养成也可以靠随机局面、推理或操作精进支撑保留。

## 五个入口合并建议

1. `compare`、`sequence`、`binary`、`targetsum` 并入以 `arithmetic` 为基础的“数学挑战”：保留五种题型，提供模式选择和各模式成绩。五款目前均是十题选择、答对计分、结束结算。合并减少 4 个入口，不删除题型。[C]
2. `beatjump` 并入 `rhythm`，作为“三键节拍跳跃”模式：两者当前核心都是按指定轨道/方向在固定时间窗口内点击，角色跳跃主要是反馈表现。保留其表现形式和成绩，减少 1 个入口。[B][AR]

不建议把所有消除、纸牌或记忆游戏合为一个：倒水的空瓶约束、堆叠三消的七槽约束、连连看的路径约束不同；经典纸牌、蜘蛛、空当的移动与信息约束不同；顺序记忆和旋律记忆有静态序列/听觉重放差异。是否共用一份文件不能作为合并依据。

## 难度系统的共性修正

1. **五个无效按钮，修 UI 比撤玩法合理。** `fruitmerge`、`solitaire`、`spider`、`freecell`、`melody` 的生成与完整对应规则分支均没有使用档位区分机制；同种子三档开局一致，额外 120 次受控输入/时间推进轨迹也一致。后者只是支持性复现，不替代源代码判断。去掉按钮即可先诚实提供一种规则；做出真分档再恢复。[PH][T][CA][B]
2. **不能从“同开局”推断假难度。** `pingpong`、`airhockey`、`xiangqi`、`chess`、`fishing` 开局也相同，但对手速度、搜索或后续时间窗口有变化。`reaction` 本就隐藏难度。它们不属于上一项。
3. **不要把数量和流程长度当作唯一难度。** `platformer`、`grapple`、`hillclimb` 应让关卡结构/操作要求变化；`sokoban`、`untangle`、`pipes` 应让谜题结构变化；不是给每款都再加一条计时器。
4. **分数必须能显示进步。** `GameDataManager` 当前按游戏 ID 保存一个最高分，没有按档位/模式分桶；十题答题主要按正确数，汉诺塔/记忆/数字寻序等使用步数得分。特别是沙画每档固定分和打地鼠跨时长共榜，最高分对复玩激励不足。按各玩法选择“用时/误点/最少步/命中率/连击”等成绩，不必全局统一成一种评分。
5. **数独/绘格等需要内容难度，AI 需要对手强度证据。** 唯一解、可解和档位强度是不同指标。当前 664 项通过不等于有了人类难度分布、AI 跨档胜率或设备上可接受的思考延迟。

## 内容与特色投入顺序

- **优先打磨已成立的核心**：拆螺丝、倒水、堆叠三消、黑洞新版、漂移新版、经典棋类/纸牌、俄罗斯方块、扫雷、2048、数独。这里既有本合集的操作特色，也有长期可玩的经典决策。
- **第二批补关卡与成绩反馈**：华容道、推箱子、绳结、滚动球、横版跳跃、钩索、图片拼图、数字寻序。先增加真正不同的任务，再增加装饰或目录数量。
- **第三批解决重叠**：数学五模式、节拍双模式先做承接；坦克与生存若无法补出明确差异，再进入下一轮合并评估，本轮不提前计为已合并。
- 不把所有“中复玩”都撤下。反应测量、记忆训练、汉诺塔有清楚的短时练习用途；但需要在名称、目标和纪录反馈中把用途表达准确。

## 下一轮验收建议

这些是建议的后续验收方式，本轮没有执行：

1. 修正任一款后，先重复本报告已知固定策略，确认不再绕过核心挑战；再验证至少 30 个独立开局，记录新的任务结构而非只数颜色/坐标变化。
2. 谜题检查可解与任务深度，动作检查速度/窗口与可达性，棋类检查代表性局面和对手强度；不同游戏不强制套同一种胜率。
3. 真机观察同一位玩家在同档前三局是否仍需新判断，并对简单→普通→困难记录完成率、用时、失误、放弃原因。机器控制器会通关不代表普通人玩得顺。
4. 每款至少明确一个“再来一局”的理由：新局面、不同解法、改善成绩或不同关卡。单局结束有“再玩”按钮不算复玩理由。
5. 若执行暂撤/合并，统一更新可见目录、路由、推荐、搜索、续玩和文案计数；保留旧记录。只有在模式入口和数据承接完成后，才按 64 个独立入口验收。
